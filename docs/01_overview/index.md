# 提案書・RFP回答運用 / 01_overview

    ## ビジョン
    RFP回答を文章生成ではなく、受注確率を上げる知識運用システムへ変える。

    ## このドメインをどう見るか
    この領域の本質は、**書類やフォームを処理すること**ではない。  
    本質は、**意思決定に必要な正当性・証拠・ルール適合性・責任所在を、期限内に接続すること**である。

    したがって本テーマは、単なる自動化ツールではなく、次の問いに答える業務基盤として捉える。

    - いま何の案件が動いているか
    - その案件はどの規則・契約・証拠に拘束されるか
    - 次に誰が何をすべきか
    - 何が例外で、何が通常か
    - 顧客価値は「処理件数」ではなく、どの結果改善で測るべきか

    ## 対象ドメイン
    RFP回答は、過去回答資産の探索、部門横断の確認、コンプライアンス表現の統一、商務条件・セキュリティ回答・法務回答の整合確保に時間がかかる。

    ## 顧客と受益者
    - **一次顧客（予算保持者）**: SaaS営業本部、官公庁入札部門、セキュリティ審査対応部門、SIer、製造業営業企画、提案センター
    - **現場受益者**: 業務担当者、管理者、監査/統制担当
    - **最終受益者**: エンドユーザー、患者、取引先、契約者、発注者など、処理遅延や品質ばらつきの影響を受ける当事者

    ## 顧客が利益を被るメカニズム
    提案作成時間短縮、回答品質平準化、期限遵守率向上、レビュー往復削減、受注勝率改善

    重要なのは、「1人の作業を軽くする」だけで終わらないことだ。  
    このドメインでは、遅延や不整合が **売上、資金化、顧客体験、規制対応、監査対応** に波及する。  
    だからこそ、プロダクトの価値は UI の便利さではなく、**業務のボトルネックを外せるか** で決まる。

    ## なぜ10億円級が狙えるか
    Fortune Business Insights は proposal management software 市場を 2025年 32.6億ドルと推計している。Loopio は2025年時点で1件のRFP作成に平均25時間を要すると紹介している。つまり課題は単なる文書生成ではなく、売上に直結する部門横断業務である。[R1][R2]

    ## 主要アクター
    - **提案責任者**: 案件戦略と最終品質責任
- **SME/専門家**: 製品・セキュリティ・法務の知識提供
- **営業**: 勝ち筋と顧客事情を持つ
- **レビューア**: 法務・セキュリティ・経営レビュー
- **顧客/発注者**: 評価基準と質問票を提示

    ## 提供するべきプロダクトの姿
    この領域では、チャットUIや文書要約だけでは不十分である。必要なのは以下を備えた「業務OS」である。

    1. 案件・ケースの集約
    2. ルールと証拠の接続
    3. 例外の検知と優先順位付け
    4. 関係者へのアサインと追跡
    5. 監査証跡と再現性
    6. 学習ループ（過去案件を次回運用へ還元）

    ## 本資料におけるプロダクト方針
    - ドメイン用語を先に定義し、実装詳細は後ろに置く
    - 生成AIは一部機能であり、中心はケース運用と状態管理
    - 既存基幹システムを置き換えるより、**既存システム間の高摩擦部分を支配する**
